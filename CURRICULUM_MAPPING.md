# Curriculum Mapping Report

## Scope and inspection

This report covers the existing training materials under `h4cker/` for the proposed **Offensive Security Fundamentals** learning path. I inspected the repository landing page and the relevant fundamentals, methodology, Linux cheat sheet, networking, offensive security, reconnaissance, Nmap, DNS reconnaissance, web application testing, and vulnerability scanner documents listed below. The repository is a large cybersecurity reference collection; it is not already organized as a beginner course.

The mapping recommends reusing source material as references and adapting it into short lessons. It does not assume that command examples are safe to execute. The initial application must present simulations only: do not run the repository's commands, scripts, scanners, or labs from the browser, and do not direct learners at public systems.

## Cross-cutting content and constraints

- **Knowledge checks:** I did not identify a set of ready-made beginner quizzes for this eight-module path. Write short checks alongside adapted lessons and label newly written material as original course explanation.
- **Practical exercises:** the repository contains command examples, scripts, scan output, labs, and links to external practice resources. Those are source references, not ready-to-run in-app simulations. Build the initial exercises from supplied fictional data and static output; make hints, expected results, verification, and reset behavior part of the course implementation phase.
- **Difficulty:** the source repository does not provide a consistent Easy/Medium/High scale for this curriculum. Assign difficulty to each exercise in the application and begin each module with a short Easy exercise.
- **Beginner suitability:** use foundational concepts and selected output excerpts. Many resources assume prior knowledge, are tool-oriented, or focus on specialized areas (for example Active Directory, exploit development, and payloads); omit these from the initial beginner sequence.
- **Content provenance:** retain the source paths beside adapted content. Any explanations, quizzes, scenarios, or assessment items written specifically for the application should be identified as newly written rather than attributed to the repository.
- **Safety:** the application’s first version must not execute shell commands, scanners, scripts, payloads, or network requests. Avoid real organizations and targets in exercise data; keep all lab interaction local and simulated.

## Repository constraints and recommendation

The source repository is organized by topic and contains Markdown references, command cheat sheets, code, labs, and external links. It does not provide the requested eight-module course, aligned knowledge checks, consistent exercise difficulty labels, or a complete set of offline exercises. Some examples are technically advanced or describe active testing. A curriculum can be assembled from selected concepts, but it will require concise beginner explanations and original, fictional exercise content.

Proceed to the application foundation only after reviewing this Phase 1 report. Keep course content separate from UI code, preserve source paths, and implement the simulated learning experience before considering any local tool integration.
